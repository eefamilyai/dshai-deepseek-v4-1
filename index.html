The same machine, re-plumbed

A standard LLM and DeepSeek V4.1-Flash predict the next token in exactly the same way. What changes is where the key/value state comes from, how much of it is kept, and how many layers have to run.

One sentence: a standard transformer gives every layer its own KV cache, computes all layers on every token, and stores that cache at 8–16 bits. V4.1 gives most layers shared KV, computes only half the depth at prefill, and stores the cache at 4 bits.

scroll
01 · the baseline

Every layer keeps its own state

each layer: own Q, own K, own V, full attention over all earlier tokens

This is the design Part 1 described, and what most models still ship. Three properties define it — and all three are what V4.1 attacks. Per-layer KV caches, dense attention that grows with the square of context, and every layer running on every token.

02 · the headline change

Global KV is projected, not computed

Cl = HL/2 · WlKV for every layer above the midpoint

The bottom half of the stack is a causal encoder. Above it, decoder layers no longer derive keys and values from their own hidden states — they project them from the encoder's final state. Prefill runs roughly half the depth.

03 · prefill

Watch half the work disappear

the encoder half runs on the full sequence; the decoder's global branch does not

Both tracks process the same prompt. The standard stack runs every layer over the whole sequence. CED runs only the encoder half at full cost, then resolves the decoder's global KV by projection — one matrix multiply instead of a full attention pass.

04 · cache sharing

Three modes, one shared cache

Full computes it · Reindex reuses it and re-selects · Reuse takes both

Compressed Sparse Attention 2 stacks compression along three independent axes: entry size, sequence length, and layers. Each layer is statically assigned one of three modes. Sharing the cache and reusing the selection are separate decisions — that decoupling is the trick.

05 · finding the needles

The first layer scans; later layers search a pool

per-query indexer cost goes from linear in context to constant

Sparse attention only reads a few entries per query, but something has to pick them — and that picker is itself linear in context. The Hierarchical Sparse Indexer restricts deeper layers to a candidate pool the first Full-mode layer already built. The first pass still scans everything.

06 · cache arithmetic

Where 890 bytes per token comes from

three multiplicative reductions, applied on top of each other

The report states V4.1-Flash's global KV cache is 890 bytes per token — roughly a quarter of V4-Flash, and about 1/437 of V1. Cross-layer reuse, sequence compression, and FP4 precision each multiply the previous one.

07 · precision

Four bits, carefully placed

quantize after RoPE · dequantize before attention · keep the local cache at FP8

Because the cache is dequantized before attention runs, the format never has to be supported by a matrix-multiply unit — it only has to survive a round trip through memory. That is what lets V4.1 use a more accurate four-bit layout than native hardware FP4 would allow.

08 · deployment

Replay a window, not a stack

exact reconstruction needs L × nwin tokens; bounded replay needs nwin

Instead of persisting the local sliding-window cache to SSD, V4.1 replays only the most recent window and accepts an approximation. The report's claim is empirical — negligible quality impact — and the same replay is simulated during post-training so the model adapts to it.

09 · the residual stream

Widening the highway, then fusing it

Xl+1 = BlXl + ClFl(AlXl)

Hyper-connections replace the single residual lane with several, letting learned mappings decide how they mix around each block. V4.1's Single-Pass mHC plus its Mega-mHC kernel halves activation memory traffic — a pure systems win, with the math unchanged.

10 · memory that isn't math

196B parameters you never multiply

hash-indexed n-gram tables, prefetched from host memory

Engram decouples memorization from computation. Knowledge lives in hash-addressed embedding tables rather than MLP weights, so retrieval costs bandwidth instead of FLOPs. Two modules at layers 1 and 14, orders {2,3,4}, 8 hash heads, FP8 tables.

11 · decode latency

Guess five tokens, verify cheaply

three draft blocks · a Markov head · a confidence head · a load-aware scheduler

DSpark drafts five positions in one pass and predicts how far the draft will survive. The scheduler combines that estimate with engine throughput curves to pick a verification length per request — turning verification depth into an economic decision.

12 · the payoff

Decode cost stops growing with context

extend context 256× and decode FLOPs rise by about a quarter

Across a 256-fold increase in context — 4K to 1M tokens — V4.1-Flash's single-token decode FLOPs rise only about 25%. If per-token decode cost is nearly flat in context length, long-horizon agents become economically viable rather than merely cheaper.
